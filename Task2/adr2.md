# ADR-2. Высокоуровневая архитектура MVP мониторинга свиноводческих ферм
## Ограниченные контексты и контейнерные диаграммы (C2)

**Дата:** 22.11.2026
**Связанные решения:** ADR-1 (контекстные диаграммы: локальная vs облачная аналитика)
**Автор:** Друзин Н.С.

---

## 1. Контекст

Требуется высокоуровневая архитектура MVP мониторинга свиноводческих ферм.
Ключевые NFR: алерт <= 5 с после события на видео, видеоаналитика в реальном
времени (миллисекунды), автономная работа фермы без интернета, синхронизация
с центром с задержкой до 10 минут. Связь с фермами нестабильна.

## 2. Ограниченные контексты

Выделение контекстов одинаково для обоих вариантов — меняется только физическое размещение
контейнеров. Разделение сделано по скорости изменений и по владельцу доменных понятий.


| Контекст | Ответственность | Основные данные |
|---|---|---|
|**Видеоаналитика**  | Захват RTSP, инференс (модель партнёров), трекинг, детекция событий (драки, задавливание, болезнь) | Видеокадры, события |
| **Мониторинг поголовья** | Состояние животных, пересчёт поголовья | Показатели, события |
| **Управление оборудованием** | Кормушки, поилки, фильтрация воды (адаптеры производителей) | Команды, телеметрия |
| **Корма и запасы** | Запасы корма, прогноз расхода | Остатки, прогнозы |
| **Уведомления** | Приоритизация, доставка уведомлений (локально дежурному; в центре — оператору) | Алерты |
| A**Управление флотом агентов**  | Управление конфигурацией, обновление моделей, health агентов | Конфиги, статусы |
| **Интеграционный API** | API для веб/мобильных приложений и внешних систем | Контракты REST |
| I**Идентфиикация** | Аутентификация, роли | Пользователи, токены |

Контексты выделены по скорости изменений и владению доменом: CV-пайплайн и
зоотехнический домен меняются независимо.


## 3. Интеграции и стек

| Интеграция | Выбор | Обоснование | Компромисс |
|---|---|---|---|
| **Устройства (кормушки и др.)** | MQTT (EMQX) на ферме | Отраслевой стандарт IoT, лёгкий | Нужен адаптерный слой под каждого производителя |
| **Камеры** | RTSP / ONVIF | Универсально для разных производителей | Гетерогенные разрешения/кодеки |
| **Шина событий на ферме** | Локальный MQTT | Простой, локальный отказоустойчивый | Для потока метрик между сервисами фермы хватает |
| **Ферма -> Центр** | Буферизация, MQTT  | Автономность, задержка до 10 мин допустима | Буферизация (72 ч) при обрыве связи |
| **Хранилище** | PostgreSQL (состояния) + ClickHouse (метрики) + S3 (фрагменты видео) | Разные модели данных под разные задачи | Дополнительная инфраструктура |
| **Очередь (центр)** | RabbitMQ | Простая, кластеризуется, не требовательна к ресурсам | При росте нагрузки до SaaS — миграция на Kafka |
| **Уведомления дежурному** | GSM/SMS + локальный шлюз | Работают без интернета | Ограниченный формат сообщений |
| **Модель CV** | Контракт инференса (gRPC) от партнёров | Замена модели без правки пайплайна | Зависимость от внешнего качества модели |


## 4. Вариант A (основное): локальный

Инференс выполняется на центральном сервере фермы (GPU). Уведомления дежурному —
локально, без интернета. В центр передаются только события и метрики.

Плюсы: полный функционал при обрыве связи; алерт за миллисекунды; нет платы за трафик.
Минусы: GPU-железо на каждой ферме; эксплуатация в поле.

## 5. Вариант B (альтернатива): гибрид с облачной аналитикой

На ферме лёгкий агент захвата, кадры/фрагменты уходят в облачный GPU-кластер.

Плюсы: дешевле железо на ферму; проще обновлять модели.
Минусы: при обрыве канала видеоаналитика останавливается (остаются только уведомеления по датчикам); трафик и хранение видео в облаке дороже.


## 6. Компромиссы

1. Брокер: RabbitMQ сейчас против Kafka в перспективе SaaS — фиксируем порог миграции заранее.
2. Трекинг особей: привязка событий к секции, а не к отдельной особи — трекинг похожих свиней надёжен только в пределах кадра.
3. Автономность против управляемости: решения принимаются на ферме, центр — только конфигурация и обновления.
4. Полнота видео против стоимости: храним не весь поток, а фрагменты вокруг событий.

## 7. Риски

| Риск | Контрмеры |
|---|---|
| Долгий обрыв связи | Буфер 72 ч на ферме; приоритезация выгрузки событий |
| Ночная съёмка / слепые зоны | ИК-камеры, «рыбий глаз» как опция (снижение качества зафиксировано) |
| Обновление модели ломает пайплайн | Версионирование контракта инференса |
| Рассинхронизация БД фермы и центра | Идемпотентные события, время источника события |
