# ADR-003. Детализация решения: уровень C3 и C4

**Дата:** 22.11.2026
**Связан с:** ADR-001 (контекст), ADR-002 (контейнеры и ограниченные контексты)
**Автор:** Друзин Н.С.

## Проблема

Для передачи решения в разработку недостаточно контейнерной диаграммы (C2): команда
должна понимать внутреннее устройство ключевого сервиса. Детализировать все восемь
ограниченных контекстов из ADR-002 на уровнях C3/C4 — это объём, который на этапе MVP
не окупается: большинство сервисов тривиальны (CRUD над справочниками, шлюзы к устройствам),
и их устройство очевидно из C2.


## Решение

Детализирован один контекст — **видеоаналитика**, как самый рискованный: именно на нём
висят жёсткие нефункциональные требования (реакция в миллисекунды, работа без внешней связи).
Для обоих вариантов решения построены:

- **C3 (компонентная)** — состав и связи компонентов сервиса;
- **C4 (диаграмма кода)** — ключевые классы пайплайна и контракт модели.

Остальные контексты осознанно оставлены на уровне C2: их достаточно для старта разработки,
а детализация будет выполняться итеративно в рамках самих сервисов.


## Ключевые решения, зафиксированные на уровне кода

1. **Модель партнёров — сменный контракт.** Инференс реализован не напрямую, а через
   интерфейс `IDetectionModel` (`load()`, `detect(frame)`, `warmup()`). Смена или обновление
   модели не затрагивает пайплайн.
2. **Пайплайн кадров — конвейер узких компонентов.** `VideoSource → FrameDecoder →
   InferenceEngine → Tracker → BehaviorClassifier → EventFactory → EventBusPublisher`.
   Каждый компонент заменяем, тестируем по отдельности.
3. **Трекинг — в пределах кадра/секции.** В `Tracker` не закладывается глобальная
   идентификация особей: особи визуально схожи, привязка событий идёт к секции.
   Глобальный трекинг — задача будущего расширения (метки/RFID).
4. **Fallback у гибридного варианта — независимый тракт.** Сенсорный fallback
   (`FallbackSensorWatcher`) живёт вне видеотракта, чтобы алерты по датчикам работали
   и при остановке инференса из-за обрыва канала.

## Компромиссы

- **Один детализированный сервис вместо всех.** Плюс: скорость, фокус на рисках.
  Минус: остальные команды стартуют с менее подробной спецификацией — митигируется
  итеративной детализацией.
- **Классический UML вместо C4-нотации на уровне кода.** C4-PlantUML покрывает уровни 1–3,
  для уровня кода канон — диаграмма классов; принципиальных потерь нет.


## Риски

- Контракт `IDetectionModel` от партнёров ещё не согласован — если формат детекций
  отличается (id, координаты, confidence), потребуется адаптер. Уровень риска: средний,
  митигируется ранним соглашением о формате.
